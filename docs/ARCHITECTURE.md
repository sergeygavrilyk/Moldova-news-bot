# Архітектура Moldova News Bot

Документ описує, що саме відбувається під час одного запуску `main.py`, які дані зберігаються і де знаходяться налаштування, які варто знати перед змінами. Номери рядків вказані для `main.py` станом на коміт `fix gemini-embedding-001` (19.10.2026); після PR #1 (30.10) вони зсунулися приблизно на +55 рядків.

## 1. Компоненти

```
┌──────────────┐  POST /actions/workflows/news_bot_run.yml/dispatches  ┌──────────────────────┐
│ cron-job.org │ ─────────────────────────────────────────────────────▶ │ GitHub Actions       │
└──────────────┘                                                         │ ubuntu, Python 3.11  │
                                                                         │ setup_db.py, main.py │
                                                                         └─────────┬────────────┘
             ┌──────────────────────────────┬──────────────────────────────┬───────┴────────────┐
             ▼                              ▼                              ▼                    ▼
   RSS 4 джерел (cloudscraper)   Google Gemini API               Supabase Postgres      Telegram Bot API
   newsmaker.md, ipn.md,          • gemini-embedding-001          • sources               • канал (новини)
   moldovalive.md, point.md       • gemini-3.6-flash              • articles (+pgvector)  • ADMIN_CHAT_ID
                                  • gemini-3.5-flash-lite         • run_analytics           (звіти, алерти)
```

Стану на диску немає: усе, що бот «памʼятає» між запусками, лежить у Supabase. Через це запуск у GitHub Actions і локальний запуск працюють з **однією й тією ж** базою.

## 2. Один запуск: покроково

### 2.0 `main()` (р. 799)
1. Перевіряє, що задані `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `GEMINI_API_KEY`, `DATABASE_URL`; інакше `exit(1)`.
2. Створює словник `stats` (воронка, беклог, публікації, токени, помилки).
3. `scrape_feeds(stats)` → `process_backlog(stats)`.
4. Будь-яка неперехоплена помилка → алерт `⚠️ ALARM` в `ADMIN_CHAT_ID`.
5. `finally`: рядок у `run_analytics`, `DELETE FROM articles WHERE created_at <= NOW() - 30 days`, звіт адміну.

### 2.1 Збір: `scrape_feeds()` (р. 376)

Для кожного джерела з `sources.status = 'ok'`:

| Крок | Правило | Куди йде відсіяне |
|---|---|---|
| Завантаження | `cloudscraper` (обхід Cloudflare), таймаут 15 с. Помилка → `error_count + 1`; при `>= 3` → `status = 'error'` | джерело пропускається |
| Обсяг | Перші **15** записів стрічки | — |
| Уже бачили | URL **або** заголовок є серед статей за останні **3 дні** | `already_seen` |
| Вік | Старше **12 годин** (`MAX_AGE_SECONDS = 43200`) за `published_parsed` | `already_seen` |
| Якість (`is_quality_article`, р. 122) | розділи URL `/sport/`, `/lume/`, `/showbiz/`…; стоп-слова (реклама, гороскопи, foto/video, спорт — RO/EN); заголовок < 15 символів; `!!!`/`???`; > 40 % великих літер | `rejected_by_keywords` |
| Семантичний дубль | Ембединг `gemini-embedding-001` (3072 виміри) від «заголовок. опис»; косинусна схожість з будь-якою статтею за 3 дні **> 0.90** | `already_seen` |
| Запис | `INSERT ... status='pending'` з картинками (до 10, без webp/avif/svg) та вектором; `ON CONFLICT (guid) DO NOTHING` | — |

Кожна стаття і кожне оновлення статусу джерела комітяться окремо: помилка однієї вставки (rollback) не скасовує вже зібране (з PR #3).

### 2.2 Відбір і публікація: `process_backlog()` (р. 496)

1. **Самовідновлення статусів**
   - `processing` старше 30 хв (за `created_at`) → `pending`.
   - `pending` старше 12 год → `expired`.
2. **Беклог**: усі `pending`, від нових до старих.
3. **Пріоритет «Україна»**: статті з ключовими словами (`ucrain`, `zelenski`, `kiev`, `odesa`, `refugiat`, `protecție temporară`, `украин`, `беженц`…) — першими в списку кандидатів.
4. **Рівномірність джерел**: решта добирається по колу між джерелами (порядок джерел випадковий) — до **40** кандидатів.
5. **Gemini-редактор** (`deduplicate_news`, р. 274):
   - на вхід: 40 кандидатів + заголовки **75** останніх опублікованих (`HISTORY`);
   - 5-кроковий алгоритм: коренева подія → кластер дублів (лишити один) → відсіяти те, що вже було в історії → стоп-теми (спорт, реклама, світовий шум/лайфстайл) → лишити 4 категорії (важливе в Молдові; українці в Молдові; рішення ЄС/світу щодо Молдови й українців; важливе в Україні);
   - відповідь — строгий JSON за схемою `NewsFilterResponse` (`keep`, `rejected[{id, entities_found, reason}]`);
   - відхилені → `status='rejected'` + `rejection_reason`.
   - **Якщо фільтр Gemini впав — публікація в цьому запуску пропускається**: нічого не відхиляється й не береться в роботу, статті лишаються `pending` до наступного запуску, помилка рахується у звіті (з PR #3).
6. **Партія**: перші **3** схвалені (`BATCH_SIZE = 3`) → `status='processing'`.
   - **Фото зі сторінки** (з PR #5): для новин партії без фото в RSS бот завантажує сторінку статті (`cloudscraper`, таймаут 10 с) і бере `og:image` / `twitter:image` (`find_og_image`). Webp/avif/svg і URL з `logo` пропускаються. Знайдене фото записується в `articles.image_urls` **до перекладу**, бо від нього залежить ліміт тексту (900/2500).
7. **Переклад** (`generate_news_texts`, р. 200) — один промпт на всю партію; правила: зберігати країну події, детальний переклад документів про тимчасовий захист, 🇺🇦 для українських тем, транслітерація топонімів, без «води» й вигадок, `<b>` для ключових фактів, ліміти 900 символів (з фото) / 2500 (без фото), 2–3 хештеги (місто латиницею або `#Moldova` + тематичні), префікс `🔄 [ОНОВЛЕНО]:` для продовжень. Тексти розділяються `|||`; кількість має збігтися з розміром партії.
8. **Чистка галюцинацій**: видаляється наголос `U+0301`, грецькі/івритські/арабські гомогліфи замінюються кириличними.
9. **Публікація** кожної новини з паузою **45 с** → `sent` або `failed`.
10. Якщо переклад не вдався — партія повертається в `pending` до наступного запуску.

### 2.3 Telegram: `send_to_telegram()` (р. 731)

| Картинок | Метод | Ліміт тексту |
|---|---|---|
| 0 | `sendMessage` | 3900 символів |
| 1 | `sendPhoto` | ≈ 920 символів мінус хештеги (ліміт підпису Telegram — 1024) |
| 2–10 | `sendMediaGroup` (підпис на першому фото) | як для 1 фото |

Довший текст обрізається з приміткою «👉 Деталі за посиланням нижче 👇». Хештеги (останній абзац) відокремлюються перед обрізанням і повертаються після нього. Наприкінці — `🔗 Джерело: <a href=...>`.

Захисти: 4 спроби з експоненційною паузою (`tenacity`); помилка `can't parse entities` → повтор без HTML; Telegram не прийняв фото → повтор текстом.

## 3. Моделі Gemini і повтори

З 30.10.2026 (PR #1, списки уточнено в PR #2) обидва виклики йдуть через спільну функцію `run_model_cascade()`: моделі пробуються по черзі зі списку.

| Завдання | Моделі за замовчуванням (по черзі) | Змінна GitHub Variables |
|---|---|---|
| Фільтр/дедуплікація (JSON) | `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` | `GEMINI_FILTER_MODELS` |
| Переклад | `gemini-3.8-flash` → `gemini-3.6-flash` → `gemini-3.5-flash-lite` (останній резерв) | `GEMINI_TRANSLATE_MODELS` |
| Ембединги | `gemini-embedding-001` (без повторів; помилка → стаття без вектора) | — |

Таймаут кожного запиту — 180 с (`HttpOptions(timeout=180_000)`); «зависла» модель = збій, каскад іде далі.

Результати перевірки 30.10.2026: працюють 3.6-flash, 3.5-flash, 3-flash-preview, 3.5-flash-lite, 3.1-flash-lite; 3.8-flash періодично 503; 3.7-flash — таймаут; 2.5-flash і 2.5-flash-lite — 404 для нових ключів.

Чому так: на безкоштовному тарифі в кожної моделі своя денна квота — flash-моделі ~20 запитів/добу, lite-моделі ~500 (публічні заміри, вересень 2026; квота — на Google-проєкт). Фільтру достатньо lite-моделі (JSON за схемою), переклад — лише flash-моделі (lite погано тримає інструкції).

Правила каскаду:
- **429 / `RESOURCE_EXHAUSTED`** → модель потрапляє в `EXHAUSTED_MODELS` і до кінця запуску не викликається; одразу наступна модель, без паузи.
- **Інша помилка** (503, порожня відповідь, неправильна кількість текстів `|||`) → пауза 5 с, наступна модель.
- Усі моделі без квоти → `GeminiQuotaExhausted`, **без повторів**; переклад повертає партію в `pending`.
- Тимчасові збої всього каскаду → `tenacity` повторює до 4 разів (фільтр: пауза 5–60 с, переклад: 15–60 с).
- Звіт адміну: `🤖 Моделі: фільтр — … | переклад — …`, `⛽ Квоту вичерпано: …`, «Невдалих спроб моделей».

Для всіх генерацій: `temperature = 0.0`, safety-фільтри вимкнені (`BLOCK_NONE`, константа `SAFETY_OFF`). Доступні моделі для ключа — `python check_models.py`.

## 4. Дані

Схема — [../db/schema.sql](../db/schema.sql).

```
pending ──▶ processing ──▶ sent
   │             │   └────▶ failed
   │             └── (помилка перекладу / завис > 30 хв) ──▶ pending
   ├──▶ rejected   (рішення Gemini, з причиною)
   └──▶ expired    (> 12 год у черзі)
усі статуси ──▶ видалення через 30 днів
```

Час у БД — UTC (`timestamp without time zone`, значення за замовчуванням сервера Supabase).

## 6. CI: `.github/workflows/news_bot_run.yml`

- Тригер: лише `workflow_dispatch` (ручний запуск або API-виклик від cron-job.org).
- `ubuntu-latest`, Python 3.11, кеш pip.
- Кроки: `pip install -r requirements.txt` → `python setup_db.py` → `python main.py`.
- Секрети: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `GEMINI_API_KEY`, `ADMIN_CHAT_ID`, `DATABASE_URL`.
- `concurrency: moldova-news-bot` — одночасно лише один запуск, наступний чекає; `timeout-minutes: 20`.
- Actions: `checkout@v5`, `setup-python@v6` (Node 24).
- Типова тривалість `main.py` — 90–275 с, з них ~2,5 хв — навмисні паузи.
